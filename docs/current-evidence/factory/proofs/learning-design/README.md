# Why hash-v1 was followed by an explicit representation

The August 13 closure record banks four terminal **offline behavior-imitation** failures. Its architecture hash matches the source from which the bounded excerpts here were taken. The architecture explicitly closes hash-v1, specifies the explicit v2 representation, and directs the next phase to a new representation identity. The implementation-readiness excerpt then distinguishes rebuilding the tensorizer/model wiring from reusing sequential replay, recurrent patterns, isolated splits and recovery.

The v3 receipt reports game-clustered exact-sequence accuracy of 64.86% for C0 versus 36.15% for B0, but 68.57% for the majority lookup. Improvement over the weaker baseline therefore did not meet the required fidelity gate. This supports the recorded decision to change the representation; it does not isolate the representation as the sole cause of failure or prove the redesign stronger.

These project-authored records are supplied as historical evidence, not executable training. No new run was performed for this package. They contain aggregate metrics, hashes and original source locations, but no game records, model weights, engine code or card data. Some historical run-identity fields remain null; the package does not fill those gaps by inference. The local paths are provenance and are not needed to read the records.

The separate July identity-embedding experiment and the later hash-v1 learning-factory branch must not be treated as the same model. The documented hash-v1-to-v2 decision chain is supported here; current v2's component implementation is described in the accompanying source excerpts and decoder demonstration. The publication does not claim an end-to-end trained, self-improving v2 player.
