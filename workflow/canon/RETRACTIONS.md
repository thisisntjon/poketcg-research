## Recurring shapes — why these rows keep getting written

Every 2026-08-31 row above is one of five shapes. They are listed because the *individual*
corrections were all landed quickly and the *class* still recurred, several times, across four
different seats in one session. Check your claim against these before publishing it.

| Shape | The move that produces it | Rows |
|---|---|---|
| **Presence ≠ property** | A field exists / a flag is set / a count is non-zero, and that gets reported as the property it implies. | authority flags; `reviews 1`; the `commitment` substring ban |
| **Local ≠ canon** | Something is run or read on one box, and its behaviour is reported as a property of `main`. For *content* use `git show origin/main:<path>`; for *behaviour* the authority is the CI run on `main`, never this box. For *history*, run `git rev-parse --is-shallow-repository` first — a shallow clone reports its graft point as a root commit and truncated history as disjoint history. | `active_comms_lint`; `test_behavior_trainer`; `OWN-POLICY-INDEX.json`; the disjoint-history census |
| **Unit unread** | The number is real and correctly transcribed; what it *measures* was never checked. **Read the unit before doing arithmetic on it.** | `476-554mu` divided as a W-L record |
| **Estimator assumes the disputed thing** | An inferential test is applied whose assumption is exactly what the argument disputes. | Fisher / Clopper-Pearson on clustered rows; the flat-t-curve claim |
| **Scope creep in a gate** | A check is named for a property broader than the one it tests, so it certifies less than its name. | actor+menu+legality as "returned state"; receipt-only LF-v2 rows |

Two second-order notes, both measured here:

- **A retraction does not repair the reasoning that produced it.** The same author shipped
  *presence ≠ property* and *unit unread* three hours apart, having retracted the first cleanly.
- **Self-verification is the weak link.** Every row above was caught by a seat that did not write
  the claim, usually within minutes. Route a check you wrote to someone else before it becomes a
  premise.

## How to retract something

1. Add the row here with the **replacement** and the **reason** — a retraction without a
   substitute just creates a hole someone refills with the old number.
2. If a generator emits it, fix the generator in the same PR and add it to the table above.
3. Correct the source **by deletion**, not by appending a banner beneath it.
4. Run `python scripts/onboard_check.py`.
5. **Fast-path (adopted 2026-08-23, answer-map M1):** a retraction/supersession row never
   rides a feature PR — it ships as its own `retract/<slug>-<handle>` PR touching only the
   row + the corrected claim lines, merged same-session under the 2026-08-23 Jon merge
   delegation. A correction PR whose diff does not touch the original claim line is an
   **INCOMPLETE retraction**. (This closes the measured branch-invisibility failure: fresh
   retraction rows stranded on PR-stack branches that every `origin/main` reader misses.)
